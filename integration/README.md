# Owned pytest adapter fixture

This original synthetic repository demonstrates only selector coverage, ordered
consecutive unit members, and once-per-shard session setup activation. Costs in
manifest.json are illustrative model inputs, not measurements. There is no CI
speedup or timing claim.

The development test tests/test_pytest_integration.py copies this fixture into a
temporary repository, exports the explicit inventory, and launches one isolated
pytest process per shard. It requires pytest >= 8.2, disables automatic external
plugin loading, supplies pytest.ini explicitly, disables pytest's cache plugin,
and records process-local starts and session setup/teardown events. No inventory
is generated by collection. No product module imports pytest or launches a
subprocess.

Run from the project root with pytest already available:

    PYTHONPATH=src python -m unittest discover -s tests -p test_pytest_integration.py -v

A missing or older pytest explicitly skips this development-only test. Release
qualification must run it without skips. The full ordinary suite uses unittest.
Real consumers must choose a trusted repository root and execution environment;
runner plugins may reorder tests and invalidate the manifest's order promise.
